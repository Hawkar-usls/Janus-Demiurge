What would an AI-written outage look like?

Nobody has blamed AI for November’s outages, but it did get me thinking. In a single week in November 2026, major incidents affecting Microsoft, the FAA, Chase, and Apple were attributed to a latent defect, a router replacement, a software bug, and an internal update, respectively. None of these incidents has been linked to AI-generated code. This paper explores what a failure caused by AI-written code with inadequate oversight might look like. Drawing on recent empirical studies and documented incidents, it presents five illustrative scenarios: a defect that passes self-written tests and remains dormant; a configuration change that precisely follows instructions; an agent fix that exacerbates the problem; a silent failure that falsely reports success; and a flaw that propagates as agents copy surrounding code. Each would pass the checks organizations typically rely on and would be described in terms similar to the November outages, without reference to AI, because code provenance is rarely documented. Evidence from Google indicates that robust review can mitigate the risk, although this capacity is expensive. The paper concludes with controls for each scenario and three AI-specific practices: recording provenance, limiting agent change size, and tiering agent permissions. AI assistance.
