# Rex research-to-code bridge v1 — review-only

This bridge makes a narrow, evidence-bound connection from Beetle research memory and Rex need discovery to the pre-admitted pure-code author.

## Sources and verdict

At each cloud run, the trusted main branch reads the Research Spine state, the exact Beetle runtime context on the durable receiver branch, delivery health from the producer branch, and the autonomous-coder accepted state. Each source is bound to a Git commit and its exact file hash. The Research Spine must contain the same Beetle context and processed sequence. Mismatch and missing evidence fail closed.

A positive **independent engineering signal** is required: an unavailable receiver ACK with an actual queued delivery, independently recorded in the producer health. The bridge never interprets scientific papers, hypothesis routes, issue text or user-controlled discoveries as instructions. It may recommend only **is_fresh(age, max_age)**, an already permitted function in the Meta Registry's ten-task pure-function author policy. This is diagnostic logic for ACK-age checks, **not** a receiver fix, credential recovery, route reopening, or evidence of completed autonomous repair.

If the admitted code catalog already includes this task, the output is truthful IDLE; no duplicate module is proposed. In every case the authority delta is zero: no trusted main change, no automatically executed model output, no automatic merge, no paid job, and no widening of the coder task catalog.

## Execution and durability

`JANUS Rex Research to Reviewed Code Need` runs on a six-hour schedule, after successful Research Spine runs, and on explicit dispatch. Pull requests execute only the negative/positive tests without source-data access or write permission. Production runs upload the generated receipt and append it to the isolated `janus/rex-code-need-state` branch under `rex/code_needs/`. Replays with the same content are idempotent; a modified historical receipt is rejected.

The output schema is `janus.rex.research_code_need.v1`. Its `PROPOSED_REVIEW_ONLY` status **does not** initiate the external code author, prove model learning, grant a Rex desire, admit a module, or implement a repair. Consuming these receipts in the Meta Registry's independent model author pipeline requires a separate scoped integration and evaluator attestation. The researcher / health / code-author boundaries remain independent.

## Acceptance

The bridge's unit tests cover provenance equivalence, stale and malformed input, ACK-count forgery, idle and deduplication behavior, escalation attempts and research-text injection. The first real production run must also prove correct Git checkouts, durable append-only receipt publishing, and a next-run replay. Only after that may the receiving coder be wired to act on an exact verified recommendation.
