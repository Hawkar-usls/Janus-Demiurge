# Demiurge Spiral Model

Demiurge no longer treats evolution as replacement in a closed loop.

```text
A0 -> B0 -> C0 -> ASCEND
                  |
                  v
A1 -> B1 -> C1 -> ASCEND
                  |
                  v
A2 ...
```

The same identity may return to the same role or physical worker slot, but it returns with accumulated memory, constraints and provenance. A slot can cycle; the **logical entity cannot reset into a ring**.

## Canonical law

```text
ENTITY_n
  + EXPERIENCE_n
  + FAILED_ATTEMPTS_n
  + CONSTRAINTS_n
       |
       v
    INTEGRATE
       |
       v
ENTITY_n+1
```

A weaker candidate is not promoted to the active frontier, but it is not thrown away. Its measured failure becomes a constraint/lesson for the next turn. A strong candidate may replace the active implementation while the parent remains in lineage.

This gives three useful outcomes:

- `ASCENDED` — active state advances and ancestry is retained.
- `INTEGRATED_LESSON` — active state stays, failed candidate becomes knowledge.
- `NO_ASCENT` — exact repeat with no new evidence, constraint or lesson.

## What “nobody is deleted” means

The law protects **learning identities and their lineage**: agents, species, architecture genomes, attempted solutions, Scout reports, evidence and lessons. It does not mean every temporary runtime object must remain active forever. A sold item can move, a buff can expire and a listing can close; those are state transitions rather than annihilation of a learning identity.

For bounded algorithms, an active window may remain bounded for performance only when overflow is retained in an archive or a provenance-preserving summary.

## Scout Swarm

Each of the 17 Scouts now has a monotonic `spiral.turn`. The previous report contributes unresolved checks and lessons, but never counts as independent evidence. Any factual claim must be grounded again in the current repository snapshot/commit.

```text
SCOUT_X@turn_n
  -> current repository evidence
  -> compare inherited constraints
  -> report + lessons
  -> SCOUT_X@turn_n+1
```

Demiurge receives every run in an append-only run directory and keeps a latest-state pointer for convenience. The latest pointer may change; the per-run lineage does not disappear.

## Compatibility

Historical JANUS modules are ancestry, not garbage. Legacy names such as `cull_weak_species()` remain as compatibility aliases where necessary, but their semantics are migrated: “cull” now routes to diagnosis/coached ascent and never marks a species extinct.
